### Architecture notes

**Why wrapper + sub-agent pattern?**
- Wrapper does the actual work (deterministic, fast, no LLM cost)
- Sub-agent only does the "decide whether to notify + compose" step
- LLM cost: only when something happened, not every 5 min (idle = no model call beyond thinking=low)
- Stagger 30s avoids 5-min boundary collisions if multiple OpenClaw instances run

**Why isolated agentTurn + announce delivery?**
- Don't pollute main session context with 5-min cron runs
- `announce` routes final response to Telegram automatically (proven pattern from daily-btc cron)
- `bestEffort=true` means delivery failures don't fail the run (cron keeps working)

**Why not heartbeat-only?**
- Heartbeat is best-effort + depends on OpenClaw session being alive
- Cron runs even if Nova main session is busy/overloaded
- Cron survives heartbeat queue backpressure

**Cost estimate:**
- Wrapper: ~0 LLM tokens (pure bash + jq)
- Idle sub-agent: ~140k input + 300 output = ~$0.005 per run, no Telegram send
- Active sub-agent: ~187k input + 480 output = ~$0.008 per run + Telegram
- Worst case (288 runs/day, all idle): ~$1.44/day = ~$43/month
- Realistic (most idle, few active): ~$0.50/day = ~$15/month

## 02:13-02:25 GMT+7 — Bug fix: stale notifications (commit d224b97)

**Bug discovered during verification:**
- Wrapper emitted ALL done items from results/ dir on every cron run
- Sub-agent sent "1 งานเสร็จ B-2026-06-22-002" to Telegram every 5 min
- Even after no new work, stale items got re-notified

**Root cause:**
- Filter was `find -mmin -6` (files modified in last 6 min)
- But items notified in prior runs still have result files modified within that window
- No state diff = no detection of "newly done" vs "already done"

**Fix (commit d224b97):**
1. Snapshot backlog done/blocked/partial IDs BEFORE tick/watch/drain
2. After drain, only emit IDs NOT in before-snapshot
3. Empty envelope = idle = no notification
4. New done = single notification with just that item

**Verification:**
- Run 19:15:50 (before fix): "sent: ok" with stale B-2026-06-22-002
- Run 19:21:42 (after fix): "sent: ok" with only NEW B-2026-06-22-004

**Side fixes during implementation:**

### Bugs found during development

**Bug 1 — bash arithmetic on ISO timestamp:**
- `last_reset` is ISO format (`2026-06-22T02:33:11`), tried `$((now_epoch - ${last_reset%.*:-0}))` → bash tried to subtract "2026-06-22T02:33:11" as number
- Fix: use `date -j -f` to parse ISO → epoch, then compare

**Bug 2 — subshell variable persistence:**
- `seen_agents="$seen_agents|$label|"` inside `while ... done` pipe — subshell can't write to parent
- Fix: collect candidates first (sort -u), then iterate in main scope

**Bug 3 — awk field number:**
- Log format: `[2026-06-22 02:29:27 +07] cloudflared-tunnel silent for 0.57h ...`
- jobname is field 4 (after [date, time, tz]), not 1 or 5
- Spent time on this because I didn't actually check the log format

**Bug 4 — BASH PATTERN MATCH gotcha (biggest bug):**
- `[[ "$state" != *"running"* ]]` with state=`\tstate=notrunning`
- "notrunning" CONTAINS "running" → pattern `*running*` MATCHES → returns FALSE
- Means if checks `!=` with pattern → false negative on notrunning
- Fix: use `*"state=running"*` (matches exact `state=running` token, not substring)
- This caused self-heal to silently fail for hours without detection
- Cost: probably 5+ minutes debugging

**Bug 5 — jq quoting:**
- `'{"state": $s}'` (single quote) works fine — was a misunderstanding, not actually broken
